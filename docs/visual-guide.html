在 Site Settings 一起設定這四項

這些都是一般環境值。範例只有格式，不能直接當成你的真實聲明。

WELLNESS_ZEPP_ONLY_CONFIRMEDtrue

你確定指定範圍內的日指標只來自 Zepp，且未手動修改，才填 true。

WELLNESS_ZEPP_ONLY_FROM日期

你確認的第一天，格式 YYYY-MM-DD。

WELLNESS_ZEPP_ONLY_THROUGH日期

你確認的最後一天。不得晚於你做出聲明的當日；不能預先涵蓋未來。

WELLNESS_ATTESTED_AT時間

你實際做出聲明的 ISO 8601 時間，需含時區。例如 2026-01-03T09:00:00+08:00 只是格式示意，不可照抄。

  1. 四項都填有效值後，按 Save 並重新部署。

卡住時，先對照這裡

連線成功，但還是讀不到資料

check_connection 只驗證固定回應。先看 get_data_health：read_disabled 查讀取開關；terms_pending 查條款開關；credential_not_configured 查 Secret 名稱與格式。configured_not_connection_verified 表示設定看似齊備，還沒有驗證上游。

按了 Save，狀態卻沒改

重新部署已核准的保存版本，等成功後再測。key、owner hash、讀取開關及日指標聲明，只要改過就需要這一步。

出現 401 / 403

用自己 Site 的正式登入與插件流程。Site owner authorization required 先查登入 Site 的 ChatGPT email 指紋；provider_credential_rejected 由你自己檢查 Intervals key。不要繞過登入或移除身分檢查。

步數、睡眠、HRV 顯示 null

source_unverified 是來源未確認或日期超出聲明；no_provider_record 是該日沒紀錄；missing_or_invalid 是欄位缺失或無效。carried_forward_not_measured 表示靜息心率只是延用值。這些都不應改成 0。

日期太長、資料太多，或被限制速度

每次查 1–31 天，含首尾。資料量過大就縮短範圍；遇到 provider_rate_limited 按回傳的等待秒數再試，不要連續重試。上游內容有矛盾時，程式會失敗，不把部分內容當成完整結果。

想回報問題，但怕洩漏資料

只描述步驟、錯誤代碼、版本及可用合成資料重現的例子。不要附 key、owner hash、email、私人 Site URL 或完整健康工具回應。若 key 洩漏，先在 Intervals 撤銷，再處理檔案與歷史副本。

  • 已完成來源聲明的日指標：步數、靜息心率、RMSSD HRV、睡眠時數／分數／品質
  • 單次日期範圍最多 31 天；活動摘要最多 100 筆

這版沒有提供

  • GPS、路線、全天心率、睡眠分期、睡眠起訖時間、訓練負荷或原始運動檔
  • 自動抓取手錶全部健康資料、固定排程同步、Zepp 即時刷新
  • 對混合來源日指標的自動認證；Strava 來源資料不透過這條連接送入 LLM

本程式不建立健康資料庫、應用快取或排程同步；Intervals、Sites 和聊天服務仍各有自己的資料政策。這不是「資料完全不離開裝置」的本機方案。
